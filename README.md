# SideRelay

Нативное приложение для установки своего IPA **с одного устройства на другое по Wi-Fi**. Интерфейс на русском. Подпись выполняется на первом устройстве; компьютер и постоянно работающий облачный сервер для установки не нужны.

**Статус:** экспериментальная реализация. GitHub Actions проверяет Rust и собирает arm64 IPA на macOS. Это не подтверждение работы на двух физических устройствах: такое испытание ещё не проведено. Сбой сопряжения или установки показывается как ошибка, а не как успешная установка.

## Скачать и установить на первое устройство

1. Скачать `SideRelay.ipa` из [Releases](https://github.com/CORBENDALLAS111/SideRelay/releases).
2. Открыть установленный **SideStore** на первом устройстве → **My Apps → +** → выбрать этот IPA.
3. Дождаться подписи и установки SideRelay через свою обычную конфигурацию SideStore.
4. При первом использовании SideRelay разрешить доступ к **Локальной сети**.

IPA в релизе не подписан под конкретный Apple Account. SideStore подписывает его при установке. GitHub Actions не получает Apple ID, сертификаты или pairing-файлы пользователя. Пока релиз не выпущен, результат успешной сборки доступен в Actions → Build SideRelay IPA → Artifacts.

## Установить IPA на целевое устройство

Нужны:

- Первое устройство с установленным SideRelay (для данного сценария — iOS 27).
- **Целевое устройство с iOS 27**, включённым Developer Mode и доступным сопряжением в его настройках. Само приложение может запускаться с iOS 18, но установка на целевое устройство со старой системой в этой версии не реализована.
- Общая Wi-Fi сеть без изоляции клиентов, интернет для обращения к Apple и anisette.
- Свой доступный IPA до 128 МБ и Apple Account, разрешающий разработку приложений.

Порядок:

1. На целевом устройстве открыть **Настройки → Wi-Fi → ⓘ** и посмотреть его **IP-адрес**.
2. На первом открыть SideRelay, выбрать IPA в «Файлах», ввести IP второго, затем открыть строку Apple Account и ввести данные для подписи. Владелец аккаунта должен доверять первому устройству: пароль вводится именно на нём.
3. Разрешить регистрацию устройства и подпись. Нажать **«Установить»**.
4. На втором открыть **Настройки → Конфиденциальность и безопасность → Режим разработчика** и выбрать сопряжение с **SideRelay**. Ввести код, показанный первым устройством. Если Developer Mode отсутствует или пункта сопряжения нет, остановиться: одной записи IP недостаточно для обхода этого ограничения.
5. Проверить показанные SideRelay имя, UDID целевого устройства и название IPA. Подтвердить установку.
6. При необходимости подтвердить вход Apple кодом 2FA. Можно запросить код на доверенные устройства или по SMS.
7. Дождаться сообщения **«Установка подтверждена iOS»**. При необходимости на целевом устройстве довериться разработчику в **Настройки → Основные → VPN и управление устройством**.

Оба устройства должны оставаться разблокированными, SideRelay — открытым на первом. При сворачивании приложение запрашивает ограниченное фоновое время; когда iOS его исчерпает, сессия отменяется. Кабель, jailbreak и LocalDevVPN **для соединения SideRelay с целевым устройством** не требуются. Для первоначальной установки самого SideRelay через SideStore используется обычная настройка SideStore, в том числе его VPN.

## Сертификаты и ограничения Apple

- Бесплатная Personal Team обычно даёт подпись на 7 дней и до трёх активных приложений. IPA с расширениями расходуют дополнительные App ID; действуют лимиты Apple.
- Сертификат, App ID и регистрация устройства остаются в Apple Account после завершения локальной сессии. Автоматического отзыва после установки нет: это сразу сломало бы подпись.
- Если доступных сертификатов нет, SideRelay **показывает список и требует два явных подтверждения** перед отзывом выбранного сертификата. Это может отключить существующие SideStore, LiveContainer и другие приложения, подписанные им. Можно отменить и использовать отдельный Apple ID. Автоматического отзыва без выбора нет.
- Приложение не импортирует закрытый ключ из твоего SideStore и не может молча использовать его сертификат. С новым одноразовым хранилищем для следующей сессии может снова понадобиться свободный сертификат.
- Специальная обработка `isideload` может встроить ключ сертификата в IPA SideStore/AltStore/другого поддерживаемого sideloader, чтобы тот мог подписывать приложения. Это копия ключа на установленном целевом устройстве.
- Не все entitlements доступны бесплатному аккаунту. DRM-зашифрованные приложения App Store, произвольные платные возможности и обход ограничений iOS не поддерживаются.

## Данные сессии

Apple ID, пароль и developer-токены не пишутся приложением в Keychain, настройки, файлы или журналы. Пароль очищается из поля сразу после открытия сессии и из принадлежащей Rust строки после входа. Это не обещание физически обнулить все внутренние копии памяти Swift и сторонних библиотек.

Для входа приложение обращается к Apple и внешнему **anisette v3** сервису (по умолчанию `https://ani.jkcoxson.com`; HTTPS origin можно изменить в «Дополнительно»). Пароль отправляется службам Apple по TLS; код SideRelay не передаёт его anisette-сервису. Собственного облачного API, аналитики и базы пользователей нет.

Pairing-ключи находятся в памяти до конца сессии. Второй телефон может сохранить доверие к сгенерированному хосту; удаление локальной сессии не отзывает это доверие на нём. При необходимости удалить соответствующее сопряжение в настройках целевого устройства. Новая сессия использует отдельную случайную идентичность.

IPA копируется во временный каталог sandbox первого устройства и получает `NSFileProtectionComplete`, затем локально проверяется и распаковывается. Копия, распакованный bundle и находящиеся в нём ключи удаляются после успеха, ошибки или отмены. После аварийного закрытия оставшиеся собственные UUID-файлы удаляются при следующем запуске. Исходный файл, выбранный в «Файлах», приложение не удаляет. Сессия ограничена 20 минутами. Отмена после начала установки не гарантирует откат: проверить целевое устройство перед повтором.

## Реализация

```text
SwiftUI + NetService (Bonjour)
    ↓ C ABI / события JSON в памяти
Rust: idevice PairableHost / RPPairing
    ↓ подтверждение кодом на целевом устройстве
Проверка mDNS authTag и pair-verify
    ↓ TLS-PSK CDTunnel / userspace TCP (jktcp)
RSD → trusted Lockdown → фактический UDID
    ↓ подтверждение устройства пользователем
isideload → Apple login / 2FA → сертификат / профиль → подпись
    ↓ повторная проверка UDID после входа
AFC upload → Installation Proxy → подтверждение iOS
```

Сообщение об успехе появляется только после успешного ответа Installation Proxy. Перед подписью имя/UDID показываются пользователю; перед установкой устройство проверяется повторно. Bonjour-адрес принимается только для указанного локального IPv4 и при совпадении `authTag` с ключом сопряжённого устройства. Приложение не создаёт публичный сервер и не открывает порты роутера.

Транспорт основан на MIT-библиотеках [idevice](https://github.com/jkcoxson/idevice) и [jktcp](https://github.com/jkcoxson/jktcp), подпись — на MIT-библиотеке [isideload](https://github.com/nab138/isideload). SideRelay написан отдельно; исходники и официальные IPA SideInstaller не включены. Пакеты зафиксированы в `core/Cargo.lock`; тексты лицензий зависимостей собираются в ресурсы IPA.

## Сборка в облаке

Push в `main` запускает `.github/workflows/build.yml` на GitHub-hosted macOS. Workflow устанавливает Rust и XcodeGen, запускает тесты, собирает Rust static library для `aarch64-apple-ios`, компилирует SwiftUI-приложение и упаковывает IPA. Никаких signing secrets для этого не нужно. Для выпуска тег `v*` публикует prerelease с IPA и SHA-256.

Локальная сборка требует Mac с Xcode и установленным iOS SDK:

```sh
brew install xcodegen
rustup target add aarch64-apple-ios
cargo test --manifest-path core/Cargo.toml --locked
IPHONEOS_DEPLOYMENT_TARGET=18.0 SDKROOT="$(xcrun --sdk iphoneos --show-sdk-path)" cargo build --manifest-path core/Cargo.toml --release --target aarch64-apple-ios --locked
python3 scripts/licenses.py
xcodegen generate
xcodebuild -project SideRelay.xcodeproj -scheme SideRelay -configuration Release -sdk iphoneos -destination 'generic/platform=iOS' -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build
python3 scripts/package.py
```

В частности, транзитивный signer `apple-codesign-quick` распространяется по LGPL-2.1-or-later. Вместе с IPA публикуется `SideRelay-source.zip` с исходниками приложения и полным деревом зависимостей для изменения библиотеки и повторной сборки/компоновки; инструкция находится в `REBUILD.txt`. Ограничений на такое изменение и обратную разработку для отладки изменений этой библиотеки нет.

## Обновление 0.2.0

Нативный Liquid Glass на iOS 26+, компактный экран, отдельное окно Apple Account, крупный PIN и анимации с поддержкой Reduce Motion. В ожидании pairing принимаются IPv4 и IPv6, probe-соединения и неудачные handshake не блокируют следующий приём. Settings → Диагностика содержит только коды этапов, без PIN, credentials, адресов и ключей.

При сбое без кода проверить: SideRelay открыт на первом устройстве, в Developer Mode выбирается на втором. Если код не появился — открыть настройки SideRelay и скопировать диагностику. Повторный выбор SideRelay в настройках запускает новую попытку без перезапуска сессии.

CI дополнительно рендерит домашний экран и экран PIN в iOS Simulator. Для этих снимков используется отдельная заглушка ядра и тестовые значения только в Debug; IPA для устройства всегда линкуется с реальным Rust-ядром. Симуляторные снимки не проверяют сопряжение с физическим телефоном.

## Обновление 0.3.0

Иллюстрация с устройствами удалена, галочки белые. Встроенный гайд подробно объясняет подготовку и роль каждого устройства, ввод PIN, 2FA и действия при ошибках. Авторы: **Zephyrax** и **CORBENDALLAS111**.

Локальная MIT-копия isideload 0.5.0 в `core/vendor/isideload` исправляет stale CPD после anisette resync: запросы SRP init и complete отправляют свежие данные одного состояния. Регрессионный тест выполняет настоящий SRP-клиент против loopback HTTP сервера, который требует hsc=434 и проверяет все три запроса. Это не тест реального Apple Account. Изменения библиотеки перечислены в `SIDERELAY-PATCHES.md`; сторонний код SideInstaller не включён.

В диагностике отдельно видны AUTH_ANISETTE_INFO, AUTH_APPLE_LOOKUP, AUTH_ANISETTE_PROVISION, AUTH_APPLE_LOGIN, AUTH_APPLE_OK и AUTH_DEVELOPER_OK. Выводятся только типизированные числовые ошибки Apple/HTTP. Текст ответов, URL ошибок и вложения upstream-отчётов не выводятся. Временные сетевые этапы ограничены таймаутами. Пароль очищается после возврата входа — как при успехе, так и при ошибке. Повторный вход с паролем на других серверах автоматически не запускается; HTTP 429 требует паузы.

Windows ADI по умолчанию: `https://ani.jkcoxson.com`. Другие серверы выбираются вручную; их доступность не гарантирована. Сервер сообщает собственный client_info, используемый библиотекой.
